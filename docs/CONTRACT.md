# A11y Toast core contract

Status: 1.0.0 unpublished release candidate; showcase/lab, reusable skins/gallery and lifecycle hardening verified locally; final-revision CI and manual acceptance pending
Updated: 2026-11-12

## Goal

Deliver small application feedback without unexpected focus movement, inaccessible action expiry, queue/timer races, or hard dependencies on another plugin.

## Approved scope

Approved scope includes a TypeScript/ESM core, BEM CSS, stable lifecycle events, overlapping pauses, an extension contract, and no wholesale code migration from the prototype. The 2026-11-12 demo scope separates a concise component showcase from an advanced lab, using a shared page shell. The approved reusable skin/gallery slice adds fifteen independent optional CSS files and a third route at `examples/designs/` / Pages `/designs/`; it moves the dedicated classic previews out of the lab while retaining the existing composer presets. Progress, promise orchestration, explicit key deduplication, the generic DOM-event adapter, the first concrete A11y Menu Button async-state adapter, an experimental ariaNotify transport, optional GSAP enter/exit, optional GSAP Flip surviving-stack motion, and an experimental element-scoped View Transition driver are implemented as optional exports. Bounded in-memory history is implemented as a separate optional export; additional ecosystem adapters and a durable notification center remain deferred.

## Resolved implementation decisions

1. The root must be mounted and outside another live region. Generated named viewport, ordered list, polite status region and assertive alert region are owned by the instance; author nodes remain untouched.
2. Queue policy is bounded FIFO, rejecting the incoming notification with a nullable result and `drop` event. `dismissAll` freezes its target set and prevents intermediate queue promotion. Re-entrant additions during clear are explicitly rejected.
3. Public timer pause/resume controls only the API-owned reason. Other reasons are hover, focus, hidden document and pending action. Snapshots expose the full reason set.
4. Ordinary content updates preserve remaining time. Explicit duration patches restart it. Loading always persists; actions/assertive notifications persist absent explicit timing overrides.
5. Semantic state remains `queued → visible → dismissed`, or `dropped` on rejection. Animation is orthogonal through `animationPhase` (`enter` / `exit` / null). `dismiss()` performs logical removal synchronously; an animated exit may keep generated DOM briefly rendered as inert + aria-hidden while its visual slot remains reserved. Destroy never waits for animation.
6. `show` reports display commitment, not animation completion. Announcements do not wait for decorative motion. Timed lifetime starts after initial display setup has finished and entrance completes or is skipped; re-entrant updates from `beforeShow`, `show`, and `afterShow` cannot start it early. `announce` reports an announcement-transport commit attempt, not speech. Announcement channels serialize commits at a fixed 100ms boundary with a 1,000ms inter-commit gap. Updates coalesce per toast; separate toasts are not content-deduplicated. Hidden documents pause pending commits.
7. Snapshot getters supplement events for demos/adapters without exposing mutation rights. There is no configure/global singleton/alias collection.
8. The single action may be event-only or have a callback. Callback promises are caught and cancellation signals are supplied. Promise/loading orchestration remains a separate optional utility rather than a core method. The utility subscribes only if its returned loading toast and manager remain active after synchronous show callbacks, and detaches on dismiss, destroy, settlement or explicit stop.
9. Add-on setup/cleanup and six selected before/after observer hooks are supported. Hooks cannot cancel or mutate the supplied snapshot; they are not awaited. Errors are isolated.
10. When the final focused toast loses all valid return targets, an owned visible empty-state focus anchor is shown until focus leaves. Disposing an entire surrounding view still needs application focus coordination.
11. Animation accepts built-in `css`, `none`, or an injected engine-neutral driver. Drivers receive a frozen context and AbortSignal; start/end/error events are typed and separate from semantic show/dismiss events. Reduced-motion and hidden-document state skip/cancel decorative motion. CSS is the default shipped driver; optional GSAP and experimental element-scoped View Transition drivers implement the same contract. GSAP Flip remains a separate layout add-on.
12. Optional runtime parameters from the initial brainstorm are intentionally narrowed: no custom API pause reason that could clear a keyboard safeguard; no global Escape; no automatic `error → assertive`; no automatic deduplication from `key`. The separate dedupe controller is opt-in, exact-key based, and never compares message text.
13. Generic source integration is explicit: a DOM-event adapter receives a concrete EventTarget and synchronous event mappings, retains adapter-local correlation IDs, and requires one announcement owner. Source-owned mappings force toast priority to `off`; adapters do not infer ownership from event names or source markup. Nested same-key commands serialize until tracking commits; other keys remain independent. Each synchronous same-key transaction accepts at most 100 commands including its initial command; overflow clears its pending work, reports one RangeError through onError with the rejected event context, and blocks further same-key work until unwind. Later external events remain usable. Refused updates retain live correlations, and disposal clears pending commands without restoring tracking afterward.
14. The first concrete ecosystem adapter targets `a11y-menu-button@^1.0.1` async state through its public `MENU_BUTTON_EVENTS` constants/types. The source status region remains the sole announcement owner. Loading/error/empty are visual mirrors on one correlation; ready dismisses rather than fabricating success copy. The peer is optional so importing toast core does not require Menu Button.
15. Announcement delivery is transport-pluggable while live regions remain the default. The experimental ariaNotify transport maps polite→normal and assertive→high, never dual-sends with live regions, and falls back to the scheduled live-region channel only when the API is absent. A Permissions Policy may suppress ariaNotify silently; neither support detection nor announce events prove assistive-technology delivery.
16. The optional GSAP driver accepts a caller-supplied GSAP instance; core never discovers a global. It owns only opacity/vertical motion and reserved lifecycle callbacks. Completion/abort/interruption call GSAP revert and then restore the exact pre-animation style attribute. Core retains reduced-motion, queue, timer, focus and DOM-removal ownership; external GSAP interruption is isolated as animation-error rather than stranding dismissal.
17. Optional GSAP Flip layout motion is implemented as an add-on using existing before/after hooks, not as a second enter/exit driver. It captures only survivors, excludes the mutated/leaving/entering toast, coalesces synchronous changes, waits for exit completion before queue-promotion reflow, and skips all measurement under reduced motion. Temporary Flip IDs/styles are restored without overwriting application-authored inline changes.
18. The experimental View Transition driver uses only `Element.startViewTransition()` on the individual toast element. Unsupported browsers settle with no motion; there is no document-scoped fallback. Active same-element phases serialize through the platform transition's `finished` boundary, abort uses `skipTransition()`, and queue/timer/focus ownership stays in core. Motion is expressed through temporary data attributes plus the optional stylesheet rather than inline styles, and authored attribute state is restored after platform finalization.

19. The optional history controller observes future show/update/dismiss payloads from one manager. It retains at most the configured lifecycle entry count (default 50; integer 1–1,000), exposes frozen plain-data reads and history-only clear, and clears/detaches on destroy or unregister. It does not backfill, persist, replay announcements/actions, mutate core state or claim a delivery audit. Observation order can differ from operation order during nested synchronous events. Full details are in `docs/HISTORY.md`.
20. Optional development diagnostics observe existing per-instance events without changing rendering or announcement behavior. A required synchronous reporter receives frozen, content-free advisory payloads for risky timing, bounded assertive bursts, queue rejection and lifecycle failures. There is no default console, DOM, storage, telemetry or network sink; reports are not WCAG findings or speech-delivery evidence.
21. Optional per-toast `icon` accepts a trusted application-authored passive HTML/SVG element, never an HTML string. Core validates and clones the supplied element during ingestion, keeps it inside an owned decorative `aria-hidden` wrapper, and excludes its DOM from snapshots/history and announcement wording. Updates may replace it or remove it with `null`; omitted icons remain unchanged. Interactive or active markup is rejected before committing a show/update. This is a constrained decoration slot, not a rich HTML renderer.
22. Per-toast `actionLayout` is `stacked` by default or opt-in `inline`. Presentation can wrap actions below content as space narrows; core retains the same native controls, focus, action cancellation, timer and announcement ownership. Snapshots/history retain the plain layout value.
23. Optional swipe dismissal is a per-instance add-on for visible, dismissible toasts using built-in `css` or `none` animation. Horizontal pointer intent locks only after movement; vertical scrolling and pinch zoom remain available. Native close buttons stay present. The add-on calls core `dismiss(id, 'swipe')`; a context-owned `holdTimer(id)` uses a distinct `gesture` pause reason and an idempotent release so caller API pauses remain intact. Gesture state and listeners are removed on cancel, dismissal, unregister and destroy. Injected animation drivers are outside this add-on's compatibility contract.
24. The visual list grows within the available viewport height by default and scrolls vertically when content exceeds it. Horizontal overflow does not create a scrollbar. The list reserves scrollbar space to keep toast width stable and visually suppresses a scrollbar caused only by entrance or exit motion. `--a11y-toast-max-height` remains a host override; `maxVisible` remains three by default, while the advanced lab explicitly allows five visible toasts.

25. Optional skins load after `a11y-toast/styles.css` through `a11y-toast/skins/{id}.css`, scoped to `.a11y-toast-region--skin-{id}`. IDs are `minimal`, `compact`, `rounded`, `classic-light`, `classic-dark`, `snackbar`, `soft`, `outline`, `solid`, `accent-rail`, `top-rule`, `split-panel`, `header-band`, `action-footer`, `monochrome`. Each supports all six tones, optional title/icon/action and long text without an external font/asset or shared skin prerequisite. No JavaScript skin option, renderer change, runtime dependency, default or version change is introduced.
26. The design gallery renders fifteen static readable non-live samples without creating a manager, toast or timer on load. Only Show or a card's Try button creates a persistent polite preview, replacing the prior preview and preserving trigger focus. Design/Tone/Include action selection affects the next preview and matching instructions only. Try action updates the same ID with “Action completed.” and removes its action. The gallery provides selectable copyable setup, a standard SVG helper and separate selected-skin/base downloads. Wide hosts use 36rem to permit the existing 32rem inline-action threshold; narrow hosts stack the action. Action footer retains its separated row below the message at every width. Owned handlers and the active manager are disposed on page exit.

## Lifecycle event contract

`TOAST_EVENTS` in `src/events.ts` is the canonical list of public event names and keys the TypeScript detail map. The core dispatches every event on its instance root with `bubbles: true`, `composed: false`, and `cancelable: false`. The shared detail contains the instance/root identity, timestamp, and visible/queued counts; item events also carry a frozen dispatch-time toast snapshot. Event details are observations, not commands, and listeners cannot cancel core work.

Initialization emits `init` after core DOM setup and instance registration, then registers configured add-ons, then emits `ready`. Showing a visible toast emits `show` before any `animation-start`; queued items emit `queue` and emit `show` only when promoted. Dismissal is logical and synchronous: `dismiss` precedes optional exit animation. `dismissAll()` emits one item-level `dismiss` event per removed toast, with no aggregate event. Pause/resume only report effective running/paused transitions. Announcement events report transport attempts or synchronous transport errors, never speech completion. Actions have invocation and error events but no success event. Active animation cancellation emits `animation-end` before `destroy`; destruction is terminal, including when add-on cleanup fails.

The complete event-by-event trigger/detail catalog is in the README Lifecycle events section. Structured metadata in `src/docs.ts` references the exported constants and is package-tested against the runtime list. Nested synchronous listeners can cause re-entrant event sequences; independent asynchronous operations have no promised relative order.

## Non-goals and limitations

No full WCAG conformance claim, publication, framework integration, persistent history, external notification API, live-region speech acknowledgment, global announcements coordinator, top-layer migration, automatic detached-host observer, rich HTML renderer or action rollback engine.

A blocking modal interaction, confirmation, required field error, or essential timed action should not be replaced with a toast. `priority: off` assumes the integrator has chosen another appropriate announcement owner.
